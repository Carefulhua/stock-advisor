# 交互式选股（v2）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 superpowers:test-driven-development 严格执行每个任务的「写失败测试 → 跑确认失败 → 实现 → 跑确认通过」红绿循环。项目非 git 仓库，计划的 commit 步骤以「全量 pytest 通过」替代。

**Goal:** 把写死的打分 Top100 选股器重做为条件驱动的交互式选股：自然语言/表单输条件 → 全市场筛选 → 预览 diff → 确认写池子 → 新股自动同步；并新增 favorites 自选股（永不移出池子）。

**Architecture:** 后端新增 `fields.py`（字段目录单一事实源）、`conditions.py`（条件模型与纯函数求值）、`parse.py`（LLM 解析）、`sync_job.py`（后台同步线程），扩展既有 `snapshot.py`/`run.py`/`storage.py`/`api/main.py`；前端新增 `/screen` 路由页面。筛选数据全部来自「腾讯全市场快照 + 业绩报表」两个全市场接口，不下载日线。

**Tech Stack:** Python 3.12 / FastAPI / pydantic / pandas / pytest；Next.js 14（App Router）/ React 18 / TypeScript / 原生 fetch；现有 `app/assistant/llm.py` 智谱 GLM 客户端。

**Global Constraints:**
- 验证方式是 pytest + 实际运行（本机 basedpyright 不可用，不做 lsp_diagnostics）
- pytest 从项目根跑：`.venv/bin/python -m pytest backend/tests -v`（pythonpath=backend）
- 全程禁止 `any` / `@ts-ignore` / 空 catch；注释仅限第 3 类必要（数据源约束、单位换算、公式、红线）
- 中文标签与提示文案，遵循现有前端风格（深色金融风、复用 CSS 变量）
- 不改动既有 P1-P3 行为：`/api/stocks` `/api/quotes/{code}` `/api/indicators/{code}` `/api/chat` 与 watchlist 表结构保持向后兼容
- 数据源单位换算必须集中在 snapshot.py 的列映射里，不在求值层做换算
