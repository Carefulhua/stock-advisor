# 选股筛选器（Screener）设计

日期：2026-10-12
状态：待用户审阅

## 背景与目标

数据底座（P1）已建成，但全市场回填成本过高（日线 ~12h、财务 ~8.7h）。用户决定：

> 不用全部股票，只做100只股的。100只股票从选股工具里面再筛选出来。

本设计定义项目内的「选股工具」：从全市场按规则打分选出 100 只，固化为自选池（watchlist），数据同步只服务这 100 只。筛选器可随时重跑。

已确认的需求决策：

| 决策点 | 结论 |
|---|---|
| 选股工具来源 | 本项目新做筛选器 |
| 筛选维度 | 流动性 + 基本面质量 |
| 100 只取法 | 打分直接取 Top 100（不做行业打散） |
| 运行方式 | 一次性选出 + 可重跑（不做自动换池调度） |
| 指标数据获取 | 方案 A：全市场快照 + 批量业绩报表 |

## 架构

```
akshare stock_zh_a_spot_em  ──┐
akshare 沪深上市公司列表      ──┼──> 硬过滤 ──> 打分 ──> Top 100
akshare stock_yjkb_em 业绩报表──┘                              │
                                                               ▼
                                    SQLite watchlist 表 + data/watchlist.txt
                                                               │
                                              scripts/sync.py --codes (复用现有同步层)
```

新模块：`backend/app/screener/`

- `snapshot.py`：拉取并合并三路数据（市场快照、上市日期、最新报告期业绩报表），输出统一 DataFrame
- `rules.py`：硬过滤 + 打分（纯函数，便于单测）
- `run.py`：CLI 入口——筛选 → 落库 → 导出 watchlist.txt

同步层不改：继续用 `scripts/sync.py --codes $(cat data/watchlist.txt)`。

## 硬过滤规则（打分前剔除）

| 规则 | 阈值/依据 |
|---|---|
| 剔除 ST | 名称含 "ST"（含 *ST） |
| 剔除北交所 | 代码非 0/3/6 开头（与 baostock is_supported 一致） |
| 剔除停牌/无成交 | 快照成交额 ≤ 0 |
| 剔除次新股 | 上市不满 1 年（上市日期来自沪深交易所上市公司列表） |
| 流动性门槛 | 流通市值 ≥ 50 亿元 或 当日成交额 ≥ 1 亿元 |

阈值存于 `config.py`，CLI 参数可覆盖。

## 打分规则（0–100）

三项指标各自在通过硬过滤的样本内做百分位归一（min-max），再加权求和：

| 维度 | 权重 | 字段 | 方向 |
|---|---|---|---|
| 成交额 | 30% | 快照当日成交额 | 越大越高 |
| 估值 | 30% | PE（动态） | 越低越高；PE ≤ 0 记 0 分 |
| 盈利增速 | 40% | 业绩报表最新报告期净利润同比增速 | 越大越高；缺失记 0 分 |

取总分降序 Top 100。权重存于 `config.py`，CLI 可覆盖。

## 自选池存储

SQLite 新表（`storage.py` 中建表，复用现有连接管理）：

```sql
CREATE TABLE IF NOT EXISTS watchlist (
    code TEXT PRIMARY KEY,
    name TEXT,
    score REAL,
    rank INTEGER,
    selected_at TEXT
);
```

- 每次重跑筛选：整表替换（先删后插，事务内）
- 同时导出 `data/watchlist.txt`（逗号分隔代码串，供 shell 命令展开）
- 已有 377 只历史 parquet 与换池天然兼容：落在新池内的股票靠增量追加续写

## 错误处理

- 三路数据任一拉取失败：重试 3 次（复用 fetchers 的退避模式），仍失败则中止并报错——筛选必须基于完整数据
- 业绩报表个别股票缺失增速：不剔除，增速分记 0
- 筛选出的有效候选 < 100：报错退出（说明硬过滤过严或数据异常），不静默出残缺池

## 测试与验收

单测（`backend/tests/test_screener.py`）：

- 打分纯函数：固定输入 DataFrame → 排序与分值稳定可断言
- 硬过滤边界：ST、北交所代码、零成交、次新股、流动性门槛各一条
- Top N 选取与不足 100 报错路径

实盘验收：

1. 真实运行 CLI 一次 → 产出 100 只 watchlist
2. `sync.py --codes $(cat data/watchlist.txt)` 日线 + 财务全部成功（失败数 0，或明确列出可解释的失败）
3. 抽查 3 只：parquet 行数合理、最新交易日为最近交易日、volume 单位为股、无重复 date

## 非目标（YAGNI）

- 不做定期自动重筛 / 换入换出调度
- 不做行业打散配额
- 不做 Web 界面展示筛选过程（P2 阶段再考虑）
- 不用逐股财务指标接口（太慢，ROE 精度不必要）
